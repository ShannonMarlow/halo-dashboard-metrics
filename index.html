Rules that apply to every panel

A difference from your existing figures most likely comes from one of these.

  1. Team filter. The default is Service Desk only. It matches the ticket's current team, not the team it was raised in. A ticket moved from Service Desk to another team leaves every count. Pick All in the Team dropdown to include every team.

  2. All ticket types count. Incidents, service requests, change requests and every other type are included. There is no ticket-type filter.

  3. Month boundaries are UK time. "This month" runs from 00:00 on the 1st, UK time, to now. It is sent to Halo in UTC, so a month starting in BST begins at 23:00 UTC on the last day of the previous month. A report that uses UTC midnight differs by one hour at each end of the month.

  4. "Closed" means current status is Closed (status ID 9), nothing else. A ticket closed and then reopened counts as open. Rejected, With Supplier and every other status count as not closed.

  5. Visibility. Counts cover only tickets that the agent the API application logs in as can see in Halo. If its role or team access is narrower than yours, its counts are lower.

  6. Child tickets may be left out.Not checked Halo's response carries include_children: false, so child tickets may be excluded by default. If your figures include child tickets, this could explain the gap.

The month

These panels follow the time picker. The dashboard opens on This month so far; choose Previous month to see the last full month.

Tickets opened in the month stat · 3 numbers

One API call fetches every ticket raised in the selected period. The dashboard keeps tickets in the selected team(s) and counts them.

Opened
Tickets whose raised date (dateoccurred) falls in the period.
Closed
Of those, how many are currently in status Closed (9). A ticket raised this month is counted here only once it is closed, even if that happens next month.
Still open
Opened − Closed. This includes Rejected, With Supplier and every other status that is not Closed.
GET /api/Tickets?count=10000&datesearch=dateoccurred&startdate={period start}&enddate={period end}
When comparing
  • A Halo report of "tickets closed this month" is not this number. For that, see All closures in the month.

Closure rate gauge

Reuses the numbers from Tickets opened in the month; there is no separate query.

Formula
Closed ÷ Opened × 100, rounded to 1 decimal place. Shows 0 when nothing was opened.
Colours
Red below 50 %, orange from 50 %, green from 75 %.
When comparing
  • It counts only tickets raised in the period. It is not "all closures ÷ all tickets opened", which would include backlog closures.
  • Example: 75 closed out of 100 opened gives 75.0 %.

All closures in the month stat · 2 numbers

A separate API call fetches every ticket closed in the period, whenever it was raised, then keeps the selected team(s).

Closed
Tickets whose closed date (dateclosed) falls in the period.
…opened in an earlier month
Of those, how many were raised before the period started: the backlog cleared.
GET /api/Tickets?count=10000&datesearch=dateclosed&startdate={period start}&enddate={period end}
When comparing
  • This is the closest match to a "closed this month" figure in Halo.
  • A ticket closed in the period counts here even if it has since been reopened.

Opened and closed per day bar chart

Uses the same two calls as the panels above, grouped by calendar day.

Opened (blue)
Tickets raised that day, grouped on the date part of dateoccurred.
Closed (orange)
Tickets closed that day, grouped on the date part of dateclosed.
Legend totals
These match Opened in the first panel and Closed in All closures.
When comparing
  • Days are UTC dates, as Halo stores them. During BST, a ticket raised between 00:00 and 01:00 counts towards the previous day.
  • Days with nothing opened or closed, usually weekends, are left out rather than shown as zero.

Right now

These panels show the current state of every open ticket and ignore the time picker. A ticket raised two years ago that is still open is counted.

Open tickets by status stat · 9 numbers

One API call fetches every ticket Halo counts as open. The dashboard keeps the selected team(s) and counts them by status ID.

Total open
Every open ticket in the selected team(s).
One tile per status
New (1), Scheduled (23), In Progress (2), Updated (22), With User (4), Approved (18), On Hold (21).
Other
Open tickets in any status not listed, such as With Supplier, Rejected or Awaiting Change Review. The tiles always add up to Total open.
GET /api/Tickets?open_only=true&count=10000
When comparing
  • Statuses are matched by ID, so renaming a status in Halo does not change the counts.
  • Halo counts Rejected as open, so rejected tickets fall into Other and Total open.

Open tickets per agent stacked bar chart

Uses the same open-ticket call, grouped by the currently assigned agent, with the same status breakdown as the tiles. Sorted by total, highest first.

Agent names
Tickets carry only an agent ID. Names come from Halo's agent list (/api/Agent), loaded once when the dashboard opens.
Unassigned
Tickets assigned to Halo's placeholder agent (ID 1).
Agent <id>
An agent ID not found in the agent list, e.g. a deleted agent.
When comparing
  • This counts who holds the ticket now, not who worked on it or who closed it this month.

Open tickets per agent (numbers) table

The same data as the chart, reused rather than queried again. It adds a Total column per agent and a TOTAL row, which equals Total open in Open tickets by status.

Waiting: On Hold and With User table

Uses the same open-ticket call, keeping only On Hold (21) and With User (4) tickets in the selected team(s). One row per ticket, longest since the last action first.

Days since last action
now − lastactiondate, in whole days, rounded down. Any action on the ticket resets it, including one that doesn't change its status.
Opened
The ticket's raised date (dateoccurred).
Agent
The currently assigned agent, named the same way as the per-agent panels.
Ticket
Links to the ticket in Halo.
When comparing
  • The row count equals On Hold plus With User in Open tickets by status.

If a figure doesn't match, note the panel, the team and month selected, and the figure you expected with its source (for example a Halo report and its filters). Pulling that exact slice from the API usually shows which rule above explains the difference.
